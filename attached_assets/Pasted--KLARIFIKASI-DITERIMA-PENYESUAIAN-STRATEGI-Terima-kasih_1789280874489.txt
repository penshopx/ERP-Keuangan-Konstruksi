## 🎯 ARSITEKTUR YANG BENAR

```
┌─────────────────────────────────────────────────────────┐
│                    CLERK (Auth Layer)                    │
│  - User management                                      │
│  - Invitation system                                    │
│  - Role assignment (org:director, org:finance, dll)    │
│  - Session management                                   │
└─────────────────────────────────────────────────────────┘
                          ↓
              [Webhook: user.created]
                          ↓
┌─────────────────────────────────────────────────────────┐
│              INTERNAL DATABASE (PostgreSQL)              │
│  - users (sync dari Clerk, hanya untuk relasi)         │
│  - user_projects (mapping Clerk user → internal projects)│
│  - projects, invoices, dll                              │
└─────────────────────────────────────────────────────────┘
```

**Flow yang benar:**
1. Director invite via **Clerk Dashboard** atau **custom UI yang call Clerk API**
2. Clerk kirim email undangan
3. User accept → jadi Clerk user
4. **Webhook** trigger → sync user ke internal database
5. Director assign project access via **custom UI** → simpan di `user_projects` table

  return 403;
