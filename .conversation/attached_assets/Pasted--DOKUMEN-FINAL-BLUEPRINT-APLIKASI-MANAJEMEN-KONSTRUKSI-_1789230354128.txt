**Target Pengguna:**
- Kontraktor (Pelaksana)
- Konsultan (Perencana & Pengawas)
- Profesional Jasa Konstruksi (PM, Site Manager, Quantity Surveyor)

**Value Proposition:**
- ✅ Real-time cost control dengan Earned Value Management (EVM)
- ✅ Automasi perpajakan konstruksi (PPh 4(2), PPN DPP Lain, PPh 23)
- ✅ Compliance PSAK 72 untuk revenue recognition
- ✅ Cashflow forecasting & working capital management
- ✅ Audit trail lengkap untuk semua transaksi

## 🎯 I. PRINSIP DESAIN MUTLAK (NON-NEGOTIABLE)

### 1. Project-Centric Architecture
Setiap transaksi keuangan **WAJIB** terikat ke `project_id` dan `wbs_code`. Tidak ada transaksi "umum" yang tidak bisa dilacak ke proyek spesifik.

**Implementasi:**
- Semua tabel transaksi memiliki foreign key ke `projects`
- Chart of Accounts (COA) menggunakan struktur 5-digit: `[Kategori]-[Proyek]-[WBS]-[SubAccount]`
- Laporan keuangan selalu bisa di-drill down sampai level item RAB

### 2. Immutable Ledger System
Data yang sudah di-posting ke ledger **TIDAK BOLEH** dihapus atau diedit langsung.

**Implementasi:**
- Setiap tabel transaksi memiliki kolom `is_posted BOOLEAN`
- Jika `is_posted = TRUE`, sistem block update/delete
- Koreksi hanya via *Reversal Journal* (debit-credit dibalik)
- Audit trail mencatat: `original_transaction_id`, `reversal_reason`, `reversed_by`

### 3. Tax-Native Design
Perpajakan bukan afterthought. Logika pajak tertanam di setiap objek transaksi.

**Implementasi:**
- Setiap `Invoice` otomatis calculate: PPh 4(2), PPN, Retensi
- Setiap `Payment_Voucher` otomatis calculate: PPh 23, PPh 21
- Validasi NPWP & SBU dilakukan saat create vendor/subkon
- Generate dokumen pajak (Faktur, Bupot) otomatis saat transaksi approved

### 4. Baseline-Driven Budgeting
RAB yang approved menjadi baseline. Realisasi selalu dibandingkan terhadap baseline.

**Implementasi:**
- `rab_headers` memiliki `version` dan `is_baseline`
- Revisi RAB membuat versi baru, tidak overwrite versi lama
- Variance analysis: `Actual vs Baseline`, bukan `Actual vs Latest`
- Change Order/Variation Order wajib untuk mengubah baseline

### 2.2. Technology Stack (Final Decision)

| Layer | Teknologi | Alasan |
|-------|-----------|--------|
| **Backend** | **Go (Golang) + Gin Framework** | Performa tinggi, concurrency model cocok untuk kalkulasi kompleks |
| **Frontend Web** | **React 18 + TypeScript + Ant Design Pro** | Komponen enterprise-ready, tabel kompleks, form validation |
| **Mobile** | **Flutter 3.x** | Cross-platform (iOS/Android), offline-capable untuk site |
| **Database** | **PostgreSQL 15+** | ACID compliance, JSON support, mature ecosystem |
| **Cache** | **Redis 7+** | Session management, dashboard cache, rate limiting |
| **File Storage** | **MinIO (S3-compatible)** | Upload dokumen kontrak, faktur, foto site |
| **Message Queue** | **RabbitMQ** | Async processing: generate PDF, export Excel, email notification |
| **Search** | **Elasticsearch** (opsional) | Full-text search untuk dokumen, audit log |
| **Monitoring** | **Prometheus + Grafana** | Metrics, alerting, performance monitoring |
| **Logging** | **ELK Stack** (Elasticsearch + Logstash + Kibana) | Centralized logging, audit trail analysis |

### 2.3. Deployment Strategy

**Phase 1 (MVP):**
- Single server deployment (Docker Compose)
- Target: 10-50 concurrent users
- Backup: Daily automated backup ke cloud storage

**Phase 2 (Scale):**
- Kubernetes cluster
- Auto-scaling berdasarkan CPU/memory usage
- Multi-AZ deployment untuk high availability
- Target: 100-500 concurrent users

**Phase 3 (Enterprise):**
- Multi-region deployment
- Database sharding untuk multi-tenancy
- CDN untuk static assets
- Target: 1000+ concurrent users

## 💼 IV. BUSINESS RULES FINAL (HARD-CODED)

### 4.1. Aturan Perpajakan

**PPh Final 4(2) - Jasa Konstruksi:**
```javascript
if (business_type === 'PELAKSANA') {
    if (qualification === 'UMKM') rate = 1.75%;
    else rate = 2.50%;
}
else if (business_type === 'PERENCANA' || business_type === 'PENGAWAS') {
    if (qualification === 'UMKM') rate = 3.50%;
    else rate = 4.00%;
}
```

**PPN - DPP Lain:**
```javascript
if (is_integrated) { // EPC / Design-Build
    dpp_lain_percent = 27.5%;
} else {
    dpp_lain_percent = 32.5%;
}
ppn_amount = contract_value * dpp_lain_percent * 11%;
```

**PPh 23 - Jasa Non-Konstruksi:**
```javascript
if (vendor.is_umkm) rate = 0.5%;
else rate = 2.0%;
```

### 4.2. Aturan Budget Control

```javascript
// Sebelum create PO atau Site Expense
const totalCommitted = sum(POs for this WBS) + sum(SiteExpenses for this WBS);
const budgetRemaining = rab_item.total_price - totalCommitted;

if (new_transaction_amount > budgetRemaining) {
    if (allow_over_budget === false) {
        throw Error('Budget exceeded. Please create Variation Order.');
    } else {
        // Allow with warning
        logWarning('Transaction exceeds budget by ${overAmount}');
    }
}
```

### 4.3. Aturan Revenue Recognition (PSAK 72)

```javascript
// Cost-to-Cost Method
const poc = actual_cost_to_date / total_estimated_cost;
const cumulative_revenue = contract_value * poc;
const revenue_this_period = cumulative_revenue - revenue_recognized_to_date;

// Onerous Contract Check
const estimated_total_cost = actual_cost_to_date + estimated_cost_to_complete;
if (estimated_total_cost > contract_value) {
    const total_loss = estimated_total_cost - contract_value;
    const loss_this_period = total_loss - loss_recognized_to_date;
    // WAJIB akui loss sekarang
    createLossAccrualJournal(loss_this_period);
}
```

### 4.4. Aturan Retensi

```javascript
// Saat create invoice
const retention_amount = invoice_dpp * retention_percent; // Biasanya 5%

// Saat release retention
if (current_date < retention_release_date) {
    throw Error('Retention cannot be released before ${retention_release_date}');
}

// Retensi tetap kena PPh Final saat dicairkan
const pph_on_retention = retention_amount * pph_final_rate;
```

## 🔐 V. SECURITY & COMPLIANCE

### 5.1. Authentication & Authorization

**Authentication:**
- JWT (JSON Web Token) dengan refresh token
- Token expiry: 15 menit (access token), 7 hari (refresh token)
- Support 2FA (Two-Factor Authentication) untuk role admin/finance

**Authorization (RBAC - Role Based Access Control):**
```
Roles:
├── SUPER_ADMIN - Full access, user management
├── DIRECTOR - View all reports, approval > threshold
├── PROJECT_MANAGER - Manage assigned projects, approval < threshold
├── SITE_MANAGER - Daily report, opname, PR
├── FINANCE_MANAGER - Invoice, payment, tax, reporting
├── TAX_STAFF - Tax calculation, document generation
├── PROCUREMENT - PO, vendor management
└── VIEWER - Read-only access
```

### 5.2. Data Security

**Encryption:**
- Password: bcrypt dengan salt
- Sensitive data (NPWP, bank account): AES-256 encryption at rest
- API communication: TLS 1.3

**Audit Trail:**
- Setiap transaksi mencatat: `created_by`, `created_at`, `updated_by`, `updated_at`, `ip_address`
- Critical actions (approve, delete, reverse) log ke `audit_logs` table
- Audit log immutable (append-only)

**Data Privacy:**
- Compliance dengan UU PDP (Perlindungan Data Pribadi)
- Data retention policy: 10 tahun untuk dokumen pajak
- Right to be forgotten: soft delete dengan anonymization

### 5.3. Compliance Checklist

- [ ] Format ekspor pajak sesuai template DJP Coretax
- [ ] Nomor faktur pajak sesuai format: `XXX.XX-XX.XXXXXXXX`
- [ ] Bukti potong sesuai format e-Bupot Unifikasi
- [ ] Arsip digital minimal 10 tahun
- [ ] Backup otomatis harian dengan retention 30 hari
- [ ] Disaster recovery plan dengan RTO < 4 jam, RPO < 1 jam

## 📈 VI. KEY PERFORMANCE INDICATORS (KPI)

### 6.1. Business KPIs (Dashboard)

**Project Health:**
- Schedule Performance Index (SPI) = EV / PV
- Cost Performance Index (CPI) = EV / AC
- Variance at Completion (VAC) = BAC - EAC
- Estimate at Completion (EAC) = BAC / CPI

**Financial Health:**
- Gross Margin per Project = (Revenue - Cost) / Revenue
- Cashflow Coverage Ratio = Cash Inflow / Cash Outflow
- Days Sales Outstanding (DSO) = (AR / Revenue) × 365
- Working Capital Ratio = Current Assets / Current Liabilities

**Tax Compliance:**
- Tax Payment Timeliness = On-time payments / Total payments
- Tax Reconciliation Variance = |Book vs Tax| / Total Tax
- Audit Findings Count = Number of tax audit findings

### 6.2. Technical KPIs

**Performance:**
- API Response Time: P95 < 500ms
- Dashboard Load Time: < 3 detik
- Concurrent Users: Support 500 users
- Database Query Time: P95 < 100ms

**Availability:**
- Uptime: 99.9% (max 8.76 hours downtime/year)
- Mean Time to Recovery (MTTR): < 30 menit

**Scalability:**
- Horizontal scaling: Add more app servers
- Vertical scaling: Upgrade database server
- Data partitioning: By project or by year

## ⚠️ VIII. RISK MITIGATION

### 8.1. Technical Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Database performance degradation | High | Indexing strategy, query optimization, read replicas |
| Data loss | Critical | Automated backup, disaster recovery plan, multi-AZ |
| Security breach | Critical | Penetration testing, security audit, WAF |
| Scalability bottleneck | Medium | Load testing, horizontal scaling, caching |

### 8.2. Business Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Tax regulation change | High | Modular tax engine, configurable rates, legal consultation |
| User adoption low | High | Training program, user-friendly UI, change management |
| Integration failure | Medium | API versioning, fallback mechanism, manual export |
| Scope creep | Medium | Strict change request process, phased delivery |
