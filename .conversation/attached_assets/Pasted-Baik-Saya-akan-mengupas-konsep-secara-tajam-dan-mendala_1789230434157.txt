## PILAR 1 — TAX ENGINE (Deep Dive)

Ini adalah bagian **paling berisiko** jika salah implementasi. Sanksi pajak bisa mencapai 100% + denda.

### 1.1. Matrix Tarif PPh Final 4(2) — PP 36/2023

```
┌─────────────────────┬─────────────────┬──────────────────┐
│ Jenis Jasa          │ Kualifikasi     │ Tarif PPh Final  │
├─────────────────────┼─────────────────┼──────────────────┤
│ PELAKSANA           │ UMKM (Kecil)    │ 1.75%            │
│ (Kontraktor)        │ Non-UMKM        │ 2.50%            │
├─────────────────────┼─────────────────┼──────────────────┤
│ PERENCANA           │ UMKM            │ 3.50%            │
│ (Konsultan Desain)  │ Non-UMKM        │ 4.00%            │
├─────────────────────┼─────────────────┼──────────────────┤
│ PENGAWAS            │ UMKM            │ 3.50%            │
│ (Konsultan MK)      │ Non-UMKM        │ 4.00%            │
└─────────────────────┴─────────────────┴──────────────────┘
```

**Aturan bisnis kritis:**
- Kualifikasi ditentukan oleh **SBU (Sertifikat Badan Usaha)** kontraktor, bukan oleh nilai kontrak.
- Satu perusahaan bisa punya **multi-SBU** → aplikasi harus support **split billing** per SBU.
- Kontraktor dengan omzet < Rp 4.8 M/tahun bisa pakai **PP 55/2022 (UMKM 0.5%)** — tapi ini **pilihan**, bukan wajib.

### 1.2. Konstruksi Terintegrasi vs Non-Terintegrasi (PENTING!)

Ini aturan yang sering salah diimplementasi:

```
KONSTRUKSI TERINTEGRASI (EPC / Design-Build):
├─ Kontraktor punya SBU Perencana + Pelaksana
├─ Dasar Pengenaan Pajak (DPP) PPh Final = 100% nilai kontrak
└─ Tarif = tarif PELAKSANA (lebih rendah)

KONSTRUKSI NON-TERINTEGRASI:
├─ Kontraktor hanya SBU Pelaksana
├─ Jika ada bagian desain → harus dipisah ke subkon perencana
├─ DPP PPh Final Pelaksana = 100% nilai pelaksanaan
└─ DPP PPh Final Perencana = 100% nilai perencanaan
```

**Implementasi di sistem:**
```javascript
function determineTaxTreatment(contract, contractor) {
    const hasDesignSBU = contractor.sbu.some(s => s.type === 'PERENCANA');
    const hasExecutionSBU = contractor.sbu.some(s => s.type === 'PELAKSANA');
    
    if (hasDesignSBU && hasExecutionSBU) {
        return {
            model: 'TERINTEGRASI',
            dpp_pph: contract.total_value,
            rate: PPH_RATES.PELAKSANA[contractor.qualification]
        };
    } else {
        // Harus split berdasarkan BOQ
        return {
            model: 'NON_TERINTEGRASI',
            splits: splitByWorkType(contract.boq),
            // Setiap split punya tarif berbeda
        };
    }
}
```

### 1.3. PPN Jasa Konstruksi — Aturan DPP Khusus

Sejak **UU HPP + PMK 70/2022**, PPN jasa konstruksi menggunakan **DPP Lain**:

```
┌─────────────────────────────┬────────────┬──────────────────┐
│ Jenis Konstruksi            │ % DPP Lain │ PPN (11% x DPP)  │
├─────────────────────────────┼────────────┼──────────────────┤
│ Terintegrasi (EPC)          │ 27.5%      │ 3.025% efektif   │
│ Non-Terintegrasi            │ 32.5%      │ 3.575% efektif   │
│ Perencana/Pengawas          │ 32.5%      │ 3.575% efektif   │
└─────────────────────────────┴────────────┴──────────────────┘
```

**Contoh perhitungan nyata:**
```
Kontrak EPC: Rp 100 Miliar (terintegrasi, PKP)

PPh Final (2.5%):     Rp 2.500.000.000  ← dipotong pemotong pajak
PPN (DPP Lain 27.5%):
  DPP = 27.5% × 100M = Rp 27.500.000.000
  PPN = 11% × 27.5M  = Rp 3.025.000.000  ← dipungut pemotong pajak

Total dipotong: Rp 5.525.000.000
Net diterima:   Rp 94.475.000.000
```

**⚠️ Edge case:** Jika pemotong pajak adalah **Bendaharawan Pemerintah** (Dinas, Kementerian, BUMN tertentu), maka **PPN dipungut oleh mereka** dan disetor sendiri ke kas negara. Kontraktor **tidak perlu setor PPN**. Aplikasi harus deteksi ini dari NPWP pemotong.

### 1.4. PPh 21 Pekerja Proyek (Metode TER — PP 58/2023)

Pekerja konstruksi (tukang, mandor, engineer site) pakai **Tarif Efektif Rata-rata**:

```javascript
const TER_RATES = {
    'TK/0': { 0-5.9M: 0.00, '6-9.6M': 0.00, '9.6-81M': 0.00 },
    'K/0':  { 0-5.9M: 0.00, '6-9.6M': 0.00, '9.6-81M': 0.00 },
    // dst...
};

// Untuk pekerja harian lepas (tukang):
// PPh 21 = 5% × (4 bulan × Rp 6.000.000 - Rp 6.000.000) × tarif
// Atau disederhanakan: PPh 21 = 5% × (bruto - PTKP proporsional)
```

**Aplikasi harus:**
- Bedakan **pekerja tetap** vs **harian lepas** vs **bulanan**.
- Hitung PTKP proporsional untuk pekerja yang masuk/keluar di tengah tahun.
- Generate **Form 1721-A1** otomatis akhir tahun.

## PILAR 2 — JOB COSTING & EARNED VALUE MANAGEMENT

Ini jantung **profitability control**. Tanpa ini, proyek bisa "kelihatan untung" di invoice tapi sebenarnya rugi.

### 2.1. Struktur Cost Code (WBS + Cost Type)

```
PROJECT: GEDUNG PERKANTORAN 10 LT
│
├── 1.0 PEKERJAAN PERSIAPAN
│   ├── 1.1 Mobilisasi         [COST: MATERIAL + LABOR + EQUIP]
│   └── 1.2 Direksi Keet       [COST: MATERIAL + LABOR]
│
├── 2.0 PEKERJAAN STRUKTUR
│   ├── 2.1 Pondasi            [COST: MATERIAL + LABOR + EQUIP]
│   ├── 2.2 Kolom Lantai 1     [COST: MATERIAL + LABOR + EQUIP]
│   └── 2.3 Plat Lantai 1      [COST: MATERIAL + LABOR + EQUIP]
│
└── 3.0 OVERHEAD PROYEK
    ├── 3.1 Gaji PM            [COST: LABOR - INDIRECT]
    └── 3.2 Listrik Site       [COST: OVERHEAD]
```

Setiap transaksi harus di-**tag** ke cost code. Tanpa ini, variance analysis tidak mungkin.

### 2.2. Earned Value Management (EVM) — 3 Metrik Kunci

```
┌─────────────────────────────────────────────────────────────┐
│ METRIK           │ RUMUS                  │ ARTINYA         │
├─────────────────────────────────────────────────────────────┤
│ PV (Planned Value)    │ Budget × % planned   │ Rencana      │
│ EV (Earned Value)     │ Budget × % actual    │ Realisasi    │
│ AC (Actual Cost)      │ Biaya aktual keluar  │ Pengeluaran  │
├─────────────────────────────────────────────────────────────┤
│ SV = EV - PV          │ Schedule Variance    │ +/- = ahead/delay │
│ CV = EV - AC          │ Cost Variance        │ +/- = under/over budget │
│ SPI = EV / PV         │ Schedule Performance Index (>1 = cepat) │
│ CPI = EV / AC         │ Cost Performance Index (>1 = hemat) │
└─────────────────────────────────────────────────────────────┘
```

**Contoh implementasi:**
```
Item: Beton Kolom L1
├─ Budget (PV planned): Rp 500.000.000
├─ Progres fisik terukur: 60%
├─ EV (Earned Value): 60% × 500M = Rp 300.000.000
├─ Biaya aktual keluar (AC): Rp 330.000.000
└─ CV = 300M - 330M = -Rp 30.000.000 (OVER BUDGET!)
```

**Aplikasi harus:**
- Integrasi dengan **opname lapangan** (bukan hanya invoice vendor).
- Support **foto dokumentasi** sebagai bukti progres.
- Alert otomatis jika **CPI < 0.9** atau **SPI < 0.9**.

### 2.3. Revenue Recognition — PSAK 72 / IFRS 15

Untuk kontrak jangka panjang, pengakuan pendapatan pakai **Percentage of Completion**:

```javascript
function recognizeRevenue(contract, periodData) {
    const totalBudget = contract.total_budget;
    const totalContractValue = contract.contract_value;
    
    // Method 1: Cost-to-Cost (paling umum di konstruksi)
    const totalCostToDate = sumActualCosts(contract.id);
    const pctComplete = totalCostToDate / totalBudget;
    
    // Revenue kumulatif yang harus diakui
    const cumulativeRevenue = totalContractValue * pctComplete;
    
    // Revenue periode ini = kumulatif - revenue yang sudah diakui sebelumnya
    const revenueThisPeriod = cumulativeRevenue - contract.revenue_recognized_to_date;
    
    // Cost periode ini = actual cost periode ini
    const costThisPeriod = periodData.actual_cost;
    
    // Gross profit
    const grossProfit = revenueThisPeriod - costThisPeriod;
    
    return {
        revenue: revenueThisPeriod,
        cost: costThisPeriod,
        gross_profit: grossProfit,
        pct_complete: pctComplete
    };
}
```

**⚠️ Aturan kritis:**
- Jika **estimated total cost > contract value** → harus langsung diakui sebagai **loss** (onerous contract), tidak boleh ditunda.
- Aplikasi harus punya fitur **"Loss Accrual"** otomatis.

## PILAR 4 — SUBKONTRAKTOR & BACKCHARGE

Ini area **paling rawan kebocoran** di proyek konstruksi.

### 4.1. Alur Opname Subkon

```
[1] Subkon selesai pekerjaan
        ↓
[2] Subkon ajukan tagihan + bukti
        ↓
[3] Site Manager opname (ukur volume aktual)
        ↓
[4] Bandingkan dengan PO/SKon
        ├─ Jika volume aktual < PO → bayar sesuai aktual
        └─ Jika ada pekerjaan tambahan → Variation Order (VO)
        ↓
[5] Hitung backcharge (jika ada):
        ├─ Kerusakan akibat subkon
        ├─ Keterlambatan
        ├─ Material yang tidak dikembalikan
        └─ Safety violation
        ↓
[6] Nilai bayar = Opname - Backcharge - Retensi - PPh
        ↓
[7] Terbitkan Bupot PPh 4(2) untuk subkon
```

### 4.2. PPh Subkon — Siapa yang Memotong?

```
KONTRAKTOR UTAMA (Anda)
    │
    ├── Subkon Pelaksana → Potong PPh 4(2) tarif pelaksana
    │
    ├── Subkon Perencana → Potong PPh 4(2) tarif perencana
    │
    └── Vendor non-konstruksi (sewa alat, katering):
        └── Potong PPh 23 (2% untuk badan, 0.5% untuk UMKM)
```

**Aplikasi harus:**
- Validasi **SBU subkon** sebelum proses pembayaran.
- Jika subkon tidak punya SBU → **tidak bisa dipotong PPh 4(2)**, harus PPh 23 atau bahkan PPh 26 (20%) jika asing.
- Generate **Bupot Unifikasi** otomatis.

## PILAR 5 — EDGE CASES KRITIS

Ini yang membedakan aplikasi "main-main" dengan aplikasi "production-grade":

| Edge Case | Implementasi yang Benar |
|-----------|------------------------|
| **Addendum/VO** | Revisi RAB harus versioned. Variance dihitung terhadap baseline terakhir yang disetujui. |
| **Denda keterlambatan** | Bukan objek PPN (bukan penyerahan BKP). Tapi mengurangi DPP PPh Final. |
| **Advance Payment** | Saat terima DP: akui sebagai **utang kerja**, bukan pendapatan. PPN dipungut saat DP. PPh dipotong saat termin. |
| **Joint Operation (KSO)** | Siapa yang billing? Biasanya **Managing Partner**. Bupot atas nama managing partner. |
| **Multi-currency** | Proyek dengan kontraktor asing → selisih kurs masuk ke **laba/rugi kurs**, bukan HPP proyek. |
| **Pekerjaan dihentikan (termination)** | Harus trigger **final accounting**: hitung revenue sampai tanggal terminasi, akui loss jika ada. |
| **Garansi bank untuk retensi** | Biaya provisi BG = overhead proyek, bukan pengurang retensi. |
| **PPh 22 Impor material** | Kredit pajak di periode impor, bukan saat material dipakai. |
